Consumer disposal coverage deliberately remains the three specified read paths. New user and fresh-operation APIs retain the legacy host's account-quiescence obligations. They do not rewire prebuilt parent use cases into a consumer. Extending the consumer API to multi-repository operations, downstream flows or deferred paging requires whole-operation/load admission and drain; no partial guard is claimed here.

The earlier SQLite IOERR_FSTAT account/key/collector was not uniquely identified. The test fixture had a source-supported teardown gap and now retains/drains actual owners, closes captured drivers and then removes files. Current suite passes do not establish unique historical attribution or an environmental cause.

Native calling has two separate counterexamples. The pristine ADR binary with its original compiler/tool pins reproduced the queued-reject CLOSED/INCOMING assertion in six of fifty iterations after REJECTED, establishing this observable failure predates migration. The unchanged current binary passed twice then again crashed in iteration three with the same AVS mute/handle-destruction signature. Baseline attribution and a fix for this separate SIGSEGV remain open. Relevant calling source/AVS pins are byte-identical to the ADR base; no cleanup or assertion was weakened and no environmental cause is claimed.

The initial current 162-test follow-up, fresh framework link and sampled Swift API check passed. Those earlier controls did not reproduce the failures; later R2 controls independently establish the assertion baseline result while preserving the crash objection. All 6,653 original archive entries and executable identities remain unchanged. Exact evidence is under `native-followup-24ff8cb/` and `native-baseline-attribution-r2/`. A concrete AVS repair is being staged and independently owned validation inputs prepared; no candidate is applied to the SDK or certified by these results.
