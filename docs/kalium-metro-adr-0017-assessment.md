Consumer disposal coverage deliberately remains the three specified read paths. New user and fresh-operation APIs retain the legacy host's account-quiescence obligations. They do not rewire prebuilt parent use cases into a consumer. Extending the consumer API to multi-repository operations, downstream flows or deferred paging requires whole-operation/load admission and drain; no partial guard is claimed here.

The earlier SQLite IOERR_FSTAT account/key/collector was not uniquely identified. The test fixture had a source-supported teardown gap and now retains/drains actual owners, closes captured drivers and then removes files. Current suite passes do not establish unique historical attribution or an environmental cause.

Current Native calling has two preserved counterexamples: a queued-reject scenario observed INCOMING after REJECTED, and an in-process repeat later crashed in AVS media-manager mute notification while another thread destroyed a call. Five separate-process runs passed. Relevant calling source and the AVS pin are byte-identical to the ADR base, and the failing test constructs its manager directly. Source analysis supports existing native queue/lifetime mechanisms, but baseline runtime reproduction and toolchain effects remain unverified. No external AVS candidate was applied, no assertion was weakened and neither failure is classified as environmental. The simplification ledger records the investigation and exact evidence paths.

The unchanged current binary also passed one original 162-test selection. These controls did not reproduce either counterexample, so no regression/dependency attribution or fix is established. The fresh current framework and sampled Swift API check passed independently. Exact source manifests, executable identities and command receipts are archived under `native-followup-24ff8cb/`.
